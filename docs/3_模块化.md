# 第 3 章 模块化

---
C++ 通过多种机制支持模块化编程，旨在提高代码的可维护性、可重用性并缩短编译时间。本章主要介绍分离编译、命名空间和错误处理。

## 3.1 引言（Introduction）

---
模块化是有效管理大型项目的核心。C++ 传统上通过头文件和源文件实现分离编译，在 C++20 中引入了模块（Modules）机制以提供更好的组织方式和更快的编译速度。

## 3.2 分离编译（Separate Compilation）

---
C++ 支持将程序划分为独立的各个部分，例如头文件（`.hpp`）和源文件（`.cpp`）。

- **头文件**：包含接口声明。
- **源文件**：包含具体实现。

这种方式允许在只修改某个源文件时，仅重新编译该文件及其依赖项，而无需重新编译整个项目。

在 `3_modularity` 示例中，我们将 `Vector` 类的声明放在 `Vector.hpp` 中，而将其实现放在 `Vector.cpp` 中。

## 3.3 命名空间（Namespaces）

---
命名空间用于将逻辑相关的组件组织在一起，并防止命名冲突。

- **定义**：使用 `namespace` 关键字。
- **使用**：通过作用域解析运算符 `::` 或 `using` 指令。

## 3.4 错误处理（Error Handling）

---
C++ 提供了多种机制来处理程序运行期间可能出现的异常情况。

### 异常（Exceptions）

当函数无法完成其任务时，可以“抛出”（`throw`）一个异常，由调用者进行“捕获”（`catch`）。

### 不变性（Invariants）

在构造函数中检查前提条件，确保对象在创建后处于有效状态。如果检查失败，通常抛出异常。

### 静态断言（Static Assertions）

使用 `static_assert` 在编译时检查条件。如果条件不满足，编译器将报错。
